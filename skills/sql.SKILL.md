Skill: SQL Agent — Read-Only SQL Execution
=========================================

Purpose
-------
Execute read-only SQL queries against enterprise databases (Postgres primary) safely and return structured results and previews for the Supervisor.

When to use
-----------
- User asks for data that must be answered from relational data (reports, aggregates, lists).

Inputs
------
- Natural language query or SQL snippet; DB connection string (managed by admin).

Outputs
-------
- `{answer: str, table: pd.DataFrame|None, query_preview: str, confidence: float}`

Step-by-step
-----------
1. If the user provided NL query, optionally use a safe LLM prompt to generate an SQL preview but never run it without admin approval in production.
2. Sanitize the SQL: reject dangerous keywords (`INSERT|UPDATE|DELETE|DROP|ALTER`) and ensure only `SELECT` statements.
3. Enforce `LIMIT` (<= configured max, default 50) by injecting or rewriting if missing.
4. Execute via SQLAlchemy using a read-only connection or within a transaction that is rolled back.
5. Return the result as a Pandas DataFrame and a natural-language summary generated by Gemini.

Decision points
---------------
- Whether to run LLM-to-SQL automatically or require a preview/confirm step.
- Row limit default and enforcement strategy.

Quality criteria
----------------
- No non-SELECT statements may be executed.
- Row limit must be enforced and verified in unit tests.
- Query results must be accompanied by a query preview and a short summary.

Files & hooks
-------------
- Implement `src/agents/sql_agent.py` and hook `before_query(sql, ctx)` for sanitisation and `after_query(rows, ctx)` for audit logging.

Example prompts
---------------
- "Translate the NL request into a safe SELECT with LIMIT 50 and execute against Postgres." 
- "Return the top 10 customers by revenue as a table and a short summary."
